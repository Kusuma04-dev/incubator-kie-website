We are happy to announce the release of **Apache KIE (Incubating) 10.3.0**.

This is more than a regular release. 10.3.0 is the first release of the **10.3.x+ stream**, a refreshed development stream we proposed to the community on the `dev@kie.apache.org` mailing list. It comes with a new repository layout, a rewritten build and release automation, a quarterly release cadence, and a platform move to Spring Boot 4 and Quarkus 3.33. It also adds new rule-authoring capabilities to Drools, extends the workflow engine, improves the editors and VS Code tooling, and ships a long list of security and stability fixes.

## The 10.3.x+ Stream

The goal of the 10.3.x+ stream is to give Apache KIE a leaner structure, lower the barrier for new contributors, and let existing contributors collaborate more efficiently. Most of the work was done in the open and tracked in a single epic, [kie-issues#2285](https://github.com/apache/incubator-kie-issues/issues/2285). This section covers what changed in the community and project structure, and the next section covers what changed in our infrastructure.

### One Repository for the Engines

Drools, OptaPlanner, Kogito Runtimes and Kogito Apps were separate repositories, each with its own build, CI and release process. They now live together in a single repository, **[`incubator-kie`](https://github.com/apache/incubator-kie)** (the former `incubator-kie-drools` repository, renamed). The code was moved with its **full Git history** and its top-level directory structure preserved, so `git log` and `git blame` keep working.

The Apache KIE code is now spread across three repositories:

| Repository | Content |
| --- | --- |
| [`incubator-kie`](https://github.com/apache/incubator-kie) | The engines: Drools, OptaPlanner, jBPM, Kogito Runtimes and Kogito Apps |
| [`incubator-kie-tools`](https://github.com/apache/incubator-kie-tools) | Tooling and front end |
| [`incubator-kie-examples`](https://github.com/apache/incubator-kie-examples) | Showcases, with a development cycle detached from `incubator-kie` and `incubator-kie-tools` |

The `incubator-kie-website` and `incubator-kie-docs` repositories are unchanged. The old `optaplanner`, `kogito-runtimes` and `kogito-apps` repositories now point to `incubator-kie` in their READMEs, and `kogito-pipelines` has been archived.

### A Leaner Scope

To focus on the core of the project, **DashBuilder**, **YaRD** and **Serverless Workflow / SonataFlow** were removed from the forward-looking `main` branches of all repositories. They are not gone: they are all kept in the **`10.2.x`** branches, so the community keeps access to them. The SonataFlow link was also removed from the Kogito website header, and the `kogito-docs` repository, which only covered SonataFlow, was frozen and archived.

### A Quicker, More Predictable Release Cadence

We revisited our release process to make it quicker and more minimal. We are now aiming to **release once a quarter**, with the next release targeted for **January 2027**.

### Easier to Contribute

Contributing is now simpler, because there are fewer repositories to learn and a build that works the same way on your machine and in CI:

- A single `git clone` of `incubator-kie` gives you the engines.
- PR checks and CI are plain scripts that you can run locally. Each repository documents how its PR checks and CI work, and the READMEs and in-repo documentation were updated for the new layout.
- If you want to contribute or have questions, say hello on [`dev@kie.apache.org`](https://lists.apache.org/list.html?dev@kie.apache.org). The [community page](/community/community) explains how to subscribe.

## Infrastructure Changes

Alongside the repository move, we rewrote how Apache KIE is built, checked and released. These changes are mostly invisible to users, but they are what makes the quarterly cadence possible.

- **PR checks are local-first.** The PR checks of `incubator-kie` and `incubator-kie-tools` were rewritten as local scripts that are invoked from GitHub Actions workflows. What runs on a pull request can be run on your own machine.
- **Release jobs are local scripts too.** The release jobs of both repositories were rewritten as local scripts invoked from Apache Jenkins, and the old ones were removed. A complete release involves two repositories and one release job in each. The only manual steps left are closing and releasing the Nexus staging repository, running the community votes, and sending the announcements. The full process is documented in the [release procedure](/community/devs/release-procedure).
- **Builds are full and reproducible.** The new CI of `incubator-kie` builds the whole project from source, and the CI/CD pipelines of `incubator-kie-tools` moved to Java 21.
- **No more build-chain.** The old `build-chain` automations for PR checks and CI were deleted, and the old Jenkins automations are being retired.
- **Examples build against `kie`.** The PR checks and local development scripts of `incubator-kie-examples` now build `incubator-kie` locally before building the examples.

## Before You Upgrade

These changes can affect existing applications:

- **Spring Boot 3 is no longer supported.** Upgrade your application to Spring Boot 4.x. KIE continues to use Jackson 2 (as Quarkus requires it), with a correct Jackson 2 integration in all Spring Boot based modules.
- **Quarkus REST.** The `quarkus-resteasy` extension has been replaced by `quarkus-rest`. Review custom REST code and dependencies.
- **Default script language in BPMN.** On-entry and on-exit scripts that do not declare a `scriptFormat` are now interpreted as Java instead of MVEL. To keep MVEL, set `scriptFormat="http://www.mvel.org/2.0"` on the script. Script tasks already defaulted to Java. This change does not affect DMN or DRL.
- **User tasks.** All human task nodes in a BPMN process that share the same `TaskName` now share a single generated model (input, output and task model classes) and a single set of REST endpoints, instead of one per node. Regular work items keep their own model and endpoints. REST endpoints are generated by default for `Human Task` only; to enable them for another work item type, set `kogito.codegen.process.workitems.<work item name>.rest.enabled=true`. Task names that resolve to the same class name (for example `My Task` and `My-Task`) now fail the build with a clear error. Review any client code that calls the generated user task endpoints.
- **Interrupting event sub process.** Behavior is now aligned with BPMN 2.0 specification, section 13.4.4.
- **Sequential mode.** Beta node sharing is disabled, `@Propagation(IMMEDIATE)` is ignored, and `ForEachNodeInstance` with async nodes no longer falls back to sequential mode.
- **Process instance locking.** The `ProcessInstance` lock is now released at transaction commit, avoiding stale reads in multi-threaded scenarios.
- **Deserialization allowlist.** Java-serialized process variables are now checked against the Drools deserialization class allowlist. If your application stores its own classes in process variables, see [Security](#security).
- **Removed.** YaRD, Serverless Workflow (SonataFlow) and DashBuilder are no longer part of Apache KIE. They remain available in the `10.2.x` branches.
- **New Flyway default.** `kie.flyway.out-of-order` is now `true` by default. See [Workflow Engine](#workflow-engine).

## What's New

### Drools

#### Rule Engine and DSL Enhancements
- **`sequence()` DSL and Phreak `SequenceNode`:** Rules can now match an ordered sequence of events. A new `sequence()` condition in the executable model DSL takes a list of steps, and each step can combine patterns with AND and OR. The rule fires only when the matching facts arrive in the declared order. The sequence is evaluated by a new Phreak node, `SequenceNode`.
- **RuleUnit DSL:** Rules defined with the RuleUnit DSL can now use rule attributes (`salience`, `noLoop`, `enabled`, `activationGroup`, `timer`, `calendars`, `dateEffective` and `dateExpires`), for example `rulesFactory.rule("HighSalience").salience(10)`. The DSL also supports STREAM event processing, enabled with `@EventProcessing(EventProcessingType.STREAM)` on the rule unit, and the CEP temporal operators `after`, `before`, `coincides`, `during`, `includes`, `meets`, `metby`, `overlaps`, `overlappedby`, `starts`, `startedby`, `finishes` and `finishedby`, for example `.after(5, 8, TimeUnit.SECONDS)`.
- **Declared enums** can now reference constants of other declared enums, for example `TARGET_PRESENT( Category.TARGET, "present" )`. A misspelled constant fails at compile time instead of at runtime.

```java
rule("seq-rule").build(
    sequence(
        pattern(toy).expr("ball", t -> t.getName().equals("ball")),
        pattern(relationship).expr("go", r -> r.getStart().equals("go"))),
    execute(() -> results.add("fired")));
```

#### Build and Tooling
- **YAML property retrieval:** Code generation now reads `application.yml` and `application.yaml` in addition to `application.properties`. Nested YAML keys are flattened to dotted property names.

### Workflow Engine
- **Dynamic process calling:** The `calledElement` of a call activity can now be an expression that is resolved from process variables when the activity runs, for example `calledElement="#{prefix + 'SubProcess'}"` or `calledElement="#{order.type}-process"`. If the expression cannot be resolved, or the resolved process does not exist, the call fails with an error.
- **Dynamic signals:** The name of a signal can be taken from a process variable, for example `<signal id="Signal_1" name="#{signalName}"/>`, so a process can wait for a signal whose name is only known at runtime.
- **Process variables:** A process can now be started with variables that it does not declare. They are kept with the process instance. You can also use `java.lang.Object` as the type of a process variable, and untyped collection variables are now supported in persistence.
- **REST work item handler:** You can limit the number of HTTP connections the handler keeps open per host with `kogito.workitem.rest.max-pool-size`. If you do not set it, the Vert.x default applies.
- **Data audit:** Data retrieved by the data-audit addons is now isolated by process id and version pair, so a query only returns data for the process and version it targets. The addons ship new database migration scripts (`V1.7.0`) that add the process id and version columns.
- **Flyway:** New `kie.flyway.out-of-order` property, `true` by default. Migrations whose version is lower than the latest applied version are now applied instead of ignored. Set it to `false` to keep the previous behavior.

### Tooling Updates

#### New DRL Editor for VS Code
10.3.0 introduces the **DRL Editor**, a VS Code extension with language support for DRL (Drools Rule Language) files, powered by a dedicated Language Server. The project was migrated into the `incubator-kie-tools` monorepo (`drools-lsp` and `drl-vscode-extension`) and is also bundled in the Kogito VS Code extension bundle. It requires Java 17 or later.

- **Code editing:** Syntax highlighting, code completion for grammar keywords, Java class names, fields and properties, and DRL `declare` types, and inlay hints for bound variables.
- **Navigation:** Go to definition for DRL and Java types, find references and rename for DRL types and bound variables, document symbols, type hierarchy, and folding ranges.
- **Diagnostics:** Syntax errors and lint checks (missing `end`, missing separators, unbalanced parentheses), an unknown-type lint with typo quick-fixes, a lint for syntax the new DRL10 parser no longer supports (with migration quick-fixes), and compile diagnostics produced on save by your project's own Drools engine.
- **Formatting:** *Format Document* and *Format Selection* rewrite a `.drl` file into one canonical shape. The formatter is configurable (line length, line endings, parenthesis padding and more), can be switched off for a region with `@formatter:off` and `@formatter:on`, and refuses to write a file rather than risk damaging it. It is also available as a command-line tool.
- **Hover and code lens:** Hover tooltips for DRL and Java types with doc-comment rendering, with Java types resolved even before a build, and reference counts on declared types.
- **File grouping:** You can declare rule groups, or adopt the rule manifests your project already has, so the editor knows which files belong together.

#### BPMN Editor
The new BPMN Editor, introduced in 10.2.0, keeps maturing, and the *Classic to New* migration guide and an extensions and conventions guide are now available.
- **REST Service Call Task:** You can now configure REST service call tasks in the editor.
- **Sub-processes:** Sub-processes can be nested, and sub-process mutations were refactored. Sequence flow labels can be moved by drag and drop, and connections are re-anchored to the facing border side when you move nodes.
- **Process properties:** A `processDuration` field was added to the global properties, call activities now get their default property values in the XML, and on-entry script formats are now persisted.
- **Events and data:** Event references on boundary events are updated when you rename or delete Messages, Errors, Escalations and Signals, and a Message type can be cleared once assigned. You can assign list type variables in multi-instance reusable sub-processes, and a sub-process with an Error Start Event no longer breaks code generation.
- **Backward compatibility:** Fixes for gateway outgoing edge conditions and for the DMN Business Rule Task, and the editor no longer removes reserved Human Task assignments without a warning.
- **Quality:** An automated end-to-end test suite now covers the editor, and edge labels are produced correctly in SVG exports.

#### DMN and Test Scenario Editors
- **DMN Editor:** Edge properties are displayed, the Java class import button works again in the Data Types panel, the palette icons are visible across resolutions, and a crash on `Any`-typed lists is fixed.
- **Test Scenario Editor:** An error message is now displayed when you open a broken `.scesim` file.
- **VS Code:** A problem that kept the BPMN and DMN editors from loading in the VS Code extension is fixed.

#### Runtime Dev Tools and Consoles
- **jBPM Dev Console for Spring Boot:** A new Dev Console for Spring Boot applications, with shared code in `jbpm-dev-console-commons`, and a *Spring Boot Compact Architecture* example. The Spring Boot Dev Console is named `jbpm-spring-boot-dev-console`, for symmetry with `jbpm-quarkus-devui`.
- **Quarkus Dev UI:** Fixes for live reload and for starting a process instance with a `Date` input variable, and for forms that could not be opened from `jbpm-quarkus-dev`. The REST work item UI also gets its missing *Async* checkbox back.
- **Management Console:** Fixes for "Update Variables" reporting and for a rendering block.
- **Data Index:** The Data Index web app now shows version information and links to the GraphQL UI.
- **Dev Deployments:** The `kube-apiserver-proxy` no longer crash-loops on arm64 clusters.

#### KIE Sandbox and Online Editors
- **Commit signing:** Git operations in workspaces now support commit signing.
- **DMN Runner:** The form now supports full namespace URIs for references within the same file.
- **CORS Proxy:** Optional TLS support, which is also configurable through the KIE Sandbox Helm chart, and security headers on its ping and fallback responses.

#### Platform and Build
- `kie-tools` follows the engines to **Spring Boot 4.1** and **Quarkus 3.33**, and migrated from `quarkus-resteasy` to `quarkus-rest`.
- The UI was upgraded from **React 17 to React 18**.
- The build toolchain moved to Node.js 24, Go 1.26 and Maven 3.9, and its CI/CD pipelines moved to Java 21.
- A [`CONTRIBUTING.md`](https://github.com/apache/incubator-kie-tools/blob/main/CONTRIBUTING.md) guide and a pull request template were added.

## Security

This release fixes a number of security vulnerabilities (CVEs) in Apache KIE and its dependencies, including:

- Unsafe deserialization in protobuf session marshalling and Java-serialized process variables. Classes not in the Drools deserialization allowlist are now rejected. If your application stores its own classes in process variables, add them to the `drools.serialization.allowedDeserializationClassPatterns` system property.
- Dependency upgrades, including Jetty, Netty, Jackson, Micrometer, reactor-core, Apache MINA SSHD, the PostgreSQL JDBC driver, the MongoDB driver, and several JavaScript dependencies of the tooling.
- A path traversal issue in the dev-deployment upload service, log forging in log output, and missing security headers in `Extended Services` and CORS Proxy responses.

The full list is in the [changelog](https://github.com/apache/incubator-kie/blob/main/CHANGELOG.md).

## Fixes

More than 40 bugs were fixed, mostly in the rule engine (Phreak, subnetworks, accumulate, executable model), the DMN engine, and process code generation. See the changelog for the complete list.
